# Odoo Run Scripts

Helper scripts for running, testing, and managing an Odoo project environment.

Scripts can be executed from **any directory** inside a project tree. `.env` and `odoo.conf` are always read from and written to the **current working directory** (`$PWD`).

## Quick Start

```bash
# 1. Go to any directory where you want config files
cd /path/to/your/project/or/subfolder

# 2. Generate .env and odoo.conf (run once per directory)
odoo-init-env

# 3. Start the Odoo server
odoo-run

# 4. Run tests
odoo-test --test mymodule
```

## Available Commands

| Command | Script | Purpose |
|---------|--------|---------|
| `odoo-init-env` | `init_env.sh` | Bootstrap `.env` and `odoo.conf` in the current directory. Use `--force` to overwrite (backs up to `.bak`), `--venv-create` to build a Python venv. |
| `odoo-run` | `run.sh` | Start the Odoo server. Pass `--log` for file logging or `--conf <file>` for a custom config. |
| `odoo-test` | `test.sh` | Run Python or JS unit tests. Supports `--test <module>`, `--testall`, `--test-js`, `--list`, etc. |
| `odoo-init` | `init.sh` | Drop and recreate the database, interactively install modules (`[Y/n]` prompts), configure module settings, and create a `pg_dump` backup in `$PWD`. |
| `odoo-install` | `install.sh` | Install, update, or uninstall modules. Use `--list` to see statuses, `--all` to install everything. |
| `odoo-reset-db` | `reset_db.sh` | Reset the database from an SQL dump in the current directory. Use `--update` to also sync Odoo source and refresh the dump. |
| `odoo-fresh` | `fresh.sh` | Quick database refresh from dump in the current directory. |
| `odoo-cloc` | `cloc.sh` | Count lines of code for all project modules via `odoo-bin cloc`. |
| `odoo-lint` | `python-lint.sh` | Run ruff, vulture, and radon on project modules. Use `--fix` to auto-fix. |
| `odoo-sync` | `sync.sh` | Compare DB records against XML data files (preview/update). |

### Helper Scripts

| Script | Purpose |
|--------|---------|
| `configure_settings.sh` | Applies `res.config.settings` after `init.sh` installs modules. Enables features (packages, variants, UoM, storage locations, etc.) via `odoo-bin shell`. Called automatically by `odoo-init`; can also be run standalone. |
| `common.sh` | Shared library sourced by all bash scripts. Loads `.env` from the current directory, validates vars, and sets `PROJECT_ROOT` automatically. |

## Configuration

- **`.env`** — environment variables (paths, DB name, ports). Created in the current directory by `odoo-init-env`. Edit directly or regenerate via `init_env.sh`.
- **`odoo.conf`** — generated by `init_env.sh` in the current directory. **Do not edit directly**; it will be overwritten.
- **`common.sh`** — shared library sourced by all bash scripts. Loads `.env` from the current directory, validates vars, and sets `PROJECT_ROOT` automatically.

## Environment Variables

| Var | Description |
|-----|-------------|
| `ODOO_ROOT` | Path to Odoo source |
| `PYTHON_PATH` | Path to venv `bin/` directory |
| `PROJECT_NAME` | Project name (default DB name prefix) |
| `DB_NAME` | Database name (usually `${PROJECT_NAME}`) |
| `HTTP_PORT` | Odoo HTTP port |
| `ODOO_SYNC_SCRIPT` | Optional path to a script that syncs/refreshes the Odoo source tree |
| `INIT_MODULES` | Optional comma-separated modules for `init.sh` (default: `base`) |

All scripts resolve paths relative to the repo root, so the project can be moved without changing `.env`.

## Installation

Scripts are installed as **wrapper scripts** in `~/.local/share/odoo/bin/`:

```bash
# Ensure the directory exists
mkdir -p ~/.local/share/odoo/bin

# Add to your shell profile (e.g. ~/.bashrc or ~/.zshrc)
export PATH="$HOME/.local/share/odoo/bin:$PATH"
```

Each wrapper script simply calls the actual script in this repository. For example, `odoo-run` contains:

```bash
#!/bin/bash
exec /path/to/odoo-scripts/run.sh "$@"
```

## Key Behavior

- `.env` and `odoo.conf` are always in the **current working directory** (`$PWD`).
- You can run `odoo-init-env` from `project-root/`, `project-root/subfolder/`, or anywhere else.
- Log files and database dumps are written to the current directory.
- The scripts themselves can live anywhere (cloned, copied, or installed via wrappers).
