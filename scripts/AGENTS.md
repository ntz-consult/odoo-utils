# Agent Notes: odoo-utils/odoo-scripts

Helper scripts for running, testing, and managing Odoo projects. Scripts are installed globally and can be run from **any directory** inside a project tree. `.env` and `odoo.conf` are always read from and written to the **current working directory** (`$PWD`).

## Global Command Access

Scripts are installed as **wrapper scripts** in `~/.local/share/odoo/bin/` for global access:

| Global Command | Script |
|---------------|--------|
| `odoo-run` | `run.sh` |
| `odoo-test` | `test.sh` |
| `odoo-init` | `init.sh` |
| `odoo-install` | `install.sh` |
| `odoo-init-env` | `init_env.sh` |
| `odoo-reset-db` | `reset_db.sh` |
| `odoo-fresh` | `fresh.sh` |
| `odoo-lint` | `python-lint.sh` |
| `odoo-cloc` | `cloc.sh` |
| `odoo-sync` | `sync.sh` |
| `odoo-direct-init` | `init-direct.sh` |
| `odoo-direct` | `direct.sh` |

**Path requirement:** `~/.local/share/odoo/bin` should be in `$PATH`.

## Required Setup (Per Project / Per Directory)

Run from **any directory** where you want `.env` and `odoo.conf` to live:

```bash
cd /path/to/your/project/or/subfolder
odoo-init-env        # Interactive setup, creates .env + odoo.conf in $PWD
```

This generates in the **current directory**:
- `.env` — environment variables (paths, DB name, ports). **Edit directly if needed.**
- `odoo.conf` — generated by `init_env.sh`. **Do not edit directly** (will be overwritten by `init_env.sh`).

## Architecture

- **`common.sh`** — sourced by all scripts. Loads `.env`, validates vars, sets `PROJECT_ROOT`, exports `ODOO_BIN`.
- **`configure_settings.sh`** — helper invoked by `init.sh` after module installation. Applies `res.config.settings` via `odoo-bin shell` to enable features (packages, variants, UoM, storage locations, etc.).
- **`.env` / `odoo.conf` lookup:** ONLY in the **current working directory** (`$PWD`). Never in the script directory.
- **Required vars:** `ODOO_ROOT`, `PROJECT_NAME`, `DB_NAME`, `PYTHON_PATH`
- **`ODOO_BIN`** is derived as `${ODOO_ROOT}/odoo/odoo-bin`

## Common Commands

```bash
# Start Odoo server (uses .env + odoo.conf in current directory)
odoo-run
odoo-run --log                    # Log to file in current directory
odoo-run --conf custom.conf       # Use different config

# Run tests
odoo-test --test <module>                  # All tests in module
odoo-test --test <module> TestClass        # Specific class
odoo-test --test <module> test_file.py:TestClass.test_name
odoo-test --testall                        # All modules
odoo-test --test-js [module]               # JS unit tests (project modules only)

# Module management
odoo-install --list               # Show module statuses
odoo-install --all                # Install all uninstalled
odoo-install --install <module>
odoo-install --update <module>
odoo-install --uninstall <module>

# Database
odoo-init                         # Drop/create DB, interactive module install [Y/n], configure settings, create pg_dump backup
odoo-reset-db                     # Restore from dump.sql in current directory
odoo-reset-db --update            # Also sync Odoo source, update all, refresh dump
odoo-fresh                        # Quick DB refresh from dump in current directory

# Lint
odoo-lint                         # ruff + vulture + radon on project modules
odoo-lint --fix                   # Auto-fix issues
odoo-lint --module <name>         # Single module only

# Odoo Direct (JSON-RPC agent access)
odoo-direct-init                  # Add odoo-direct credentials to .env (interactive)
odoo-direct --test                # Test connection using .env credentials
```

## Testing Quirks

- Python tests use Odoo's `--test-tags` format: `/{module}:{Class}.{method}`
- JS tests use HOOT filtering: `mymodule/static/tests/foo.test.js` → `@mymodule/foo`
- `--test-js` without module runs tests for **all project modules** (fast)
- `--test-js-all` runs full desktop suite including Odoo core (slow)
- `--testall` updates all modules and runs all tests; may be slow for large projects

## XML Data Sync Utility

`sync.py` + `sync.sh` compare database records against XML data files:

```bash
odoo-sync --module <module>              # Preview discrepancies
odoo-sync --module <module> --detail     # Show field-level differences
odoo-sync --module <module> --update     # Rewrite XML files after confirmation
```

Detects: missing in DB, missing in XML, field differences. Reads DB credentials from `odoo.conf` in the current directory.

## File Organization

Scripts can be run from **anywhere** in the project tree:

```
project-root/
├── run-scrips/             # Scripts directory (copied or cloned)
│   ├── common.sh           # Shared environment loader
│   └── *.sh                # Individual scripts
├── <modules>/              # Odoo modules (addons)
│   └── ...
└── any_folder/
    └── sub_folder/
        ├── .env            # Created by odoo-init-env in current dir
        └── odoo.conf       # Generated by odoo-init-env in current dir
```

**Important:** `.env` and `odoo.conf` are always in the directory from which you run the commands.

## Odoo Direct Environment Variables

`odoo-direct-init` writes these to `.env` for use by `odoo-direct`:

| Var | Description |
|-----|-------------|
| `ODOO_DIRECT_URL` | Odoo instance URL (e.g. `https://mycompany.odoo.com`) |
| `ODOO_DIRECT_DB` | Database name |
| `ODOO_DIRECT_USER` | Username (email) |
| `ODOO_DIRECT_API_KEY` | API key (not password) |

## Important Defaults

- Default Odoo root: `~/Odoo/V19`
- Default venv path: `PROJECT_ROOT/.venv`
- Default HTTP port: `8096`
- Default DB socket: `/run/postgresql`
- Dump file location: `$PWD/dump_${PROJECT_NAME}.sql` (current directory)
- Log file location: `$PWD/${PROJECT_NAME}.log` (current directory)
